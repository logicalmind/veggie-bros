### R01 — Pits cannot kill you  [REVIEW]

**Files:** `src/main.js` (line 274), `src/level.js` (line 10 — read only, do not change).
**Symptom:** every gap in all three levels is a survivable trampoline. `tileAt` returns `'X'` for
`ty >= ROWS`, so each 2-row pit has an invisible solid floor at y=240. The player rests at
`y = 15*16 - 12 = 228`, but death needs `p.y > VIEW_H + 32` = 272 → unreachable. The whole
`deadPit` path (`main.js:274-279`, `player.js:56`, `render.js:183`) is dead code.
**Evidence:** dropping into 1-1's pit at col 58 → `landed {frame:9, y:228, feet:240}`, `dead=false`;
from that floor a jump peaks at `y=144.2` vs surface 196 → escapes. Independent confirmation from
two audits. This is why CP9 (the 1-2 pit) never passed (`RESUME.md:47`).
**Fix (decision 5):** in `main.js`, replace the pit test with a size-independent floor check:
`if (p.y + p.h >= ROWS * TILE) { ... }` — import `ROWS` from `config.js`. Keep `killPlayer(p, true)`
and the existing SFX/`dyingT` wiring. Do NOT change `tileAt`.
**Check `R01`:** small player released into 1-1 col 58 → within 30 steps `p.dead === true` and
`p.deadPit === true`; big player (h=26) same result; standing on normal ground (feet 208) for 300
steps → `p.dead === false` (no false positives). Also assert the player never comes to rest with
`p.y === 228`.
**Notes:** R29 and R33 depend on this. `architecture.md:73` ("out-of-range tiles: solid … below")
stays literally true but gains a clarifying sentence in R34.

### R02 — A legal boss stomp damages you ~12% of the time  [REVIEW]

**Files:** `src/main.js:244-256`.
**Symptom:** you jump on the boss, it registers (`bossHit`, `+500`), and then you take damage on the
very next frame. As small Poppy that is instant death on boss hits 1 and 2.
**Mechanism:** main sets `p.vy = STOMP_BOUNCE` but never separates the boxes and never suppresses
boss contact while you are bouncing away. The bounce lifts only `360/60 - 2300/3600 = 5.36` px in one
step, so if first-contact penetration exceeded 5.36 px (possible up to `MAX_FALL*dt` = 7 px) the next
frame still overlaps and `p.vy` is now negative → the `p.vy > 0` stomp test fails → `hurtPlayer`.
**Evidence:** `landings 394 | hurt within 4 frames of a legal stomp: 48` (~12%), worst starting
penetration 6.14 px, `{"dropFrom":20,"pen0":6.14,"since":1,"vy":-321.7,"penNow":0.78}`.
**Fix:** on a successful stomp, place the player on top of the boss before bouncing:
`p.y = boss.y - p.h; p.vy = STOMP_BOUNCE;` Mirror the separation for turnips at `:232`
(`p.y = e.y - p.h;`) for consistency.
**Check `R02`:** sweep the drop height 0..24 px in 0.5 px steps onto the boss; assert zero
`hurtPlayer` calls within 5 frames of any successful stomp, and that every landling either stomps
or is hurt exactly once (no double-resolution).
**Notes:** do NOT apply the `<10`→`<14` change from `RESUME.md:53` — decision 7 withdraws it.
R03 refines the same code next; keep your change small and local.

### R03 — Walking into an enemy's flank counts as a stomp  [REVIEW]

**Files:** `src/main.js:227` and `:245`, `src/player.js` (add one field).
**Symptom:** descending into the *side* of a turnip gives `+200`, a squash and a bounce instead of
a hit. Free kills, free score, and enemies die when you never touched their heads.
**Mechanism:** the only test is `p.vy > 0 && p.y + p.h - e.y < 10` — 10 px of a 12 px turnip (83% of
its body). It never checks where the feet were last frame, nor lateral penetration.
**Evidence:** 720 seeded approaches against a grounded turnip →
`legitStomp 8  FALSE_STOMP(lateral) 19  hurt 693`.
**Fix (decision 6):** at the end of `updatePlayer` record `p.prevBottom = p.y + p.h;`. Require
`p.prevBottom <= e.y + 0.5` in **both** stomp tests (`:227`, `:245`), keeping R02's separation. The
window literal becomes irrelevant — leave `10` in place or drop it, but the prev-frame test must be
the authority. Initialize `prevBottom` in `makePlayer`.
**Check `R03`:** same 720-approach sweep: assert lateral approaches never squash, and that a genuine
over-the-top stomp still works from drop heights 0..24 px (no regression of R02).
**Notes:** run after R02 (same code region). This is the change that makes the `<14` idea unnecessary.

### R05 — One-shot input flags leak across game states

**Files:** `src/main.js:117-325`.
**Symptom:** press jump while paused → Poppy jumps the instant you unpause. Press **R** once during
play → your *next* pause instantly restarts the level. Press **Enter** during play → the moment you
reach GAME_OVER/WIN it flashes straight back to TITLE. Same class: press P while dying → the respawn
starts paused.
**Mechanism:** `jumpPressed`/`start`/`pausePressed`/`restartPressed` are consumed only inside some
branches. TITLE consumes just `start`; PAUSED just `pause`+`restart`; the `p.dead` branch
(`:131-140`) and `LEVEL_CLEAR` (`:303-315`) consume almost nothing. Anything unconsumed survives
indefinitely.
**Evidence:** jump pressed while paused → `sfx:jump` fires on the resume frame with no held input;
a single deliberate P press produced `musicStop → musicStart` because a stale `restartPressed`
latched and fired in PAUSED.
**Fix:** add a local `endFrame()` (or `clearTransients()`) in `main.js` that resets the transient
one-shot flags on the `input` object, and call it on **every** return path out of `update()` —
including the early returns in the `p.dead` branch, `onGate`, `onBossDown` and each state branch.
Keep the existing `consume*()` helpers as the authority for reads; this only guarantees nothing
survives a frame it was not consumed in. Prefer one `endFrame()` at the end plus a `finally`-style
wrapper over sprinkling calls, if you can do it without restructuring the state machine.
**Check `R05`:** for each state (TITLE, PLAYING, PAUSED, PLAYING-while-dead): set each one-shot flag,
run one frame, assert the flag is false and that no unintended side effect occurred (no `musicStart`,
no `sfx:jump`, no `loadLevel`) in a state that should ignore it.
**Notes:** **must land before R10** — R10 adds touch buttons that write these same flags.

### R06 — Window blur latches keys, and latched `jump` kills jumping entirely

**Files:** `src/input.js`.
**Symptom:** alt-tab while holding right and Poppy runs into a wall forever. Worse: because
`input.js:55` only sets `jumpPressed` when `!input.jump`, a single missed keyup means **jump stops
responding completely**, and `player.js:90`'s jump-cut never applies → permanent full-height jumps.
`run` latches identically. Also: nothing pauses the game when the tab is hidden, so audio keeps
playing (`setInterval` is not paused) — see R07.
**Fix:** export a `resetInput()` in `input.js` that zeroes `left/right/run/jump` (leave the one-shot
flags to R05's `endFrame`), and call it from a window `blur` listener plus
`document.visibilitychange` when `document.hidden`. Also bind a window-level `pointerup` /
`pointercancel` that releases touch directions — for **mouse/pen** on hybrid devices there is no
implicit pointer capture, so a `pointerdown` on a button followed by release elsewhere never reaches
the button's `pointerup`. (For touch, the spec's implicit capture already retargets `pointerup` to
the button, and `pointercancel` is already bound at `:93` — so do not add per-button `pointerleave`
handlers, which would wrongly cancel a finger that slid off mid-press.)
**Check `R06`:** drive a frame with `input.right = true`, simulate blur, assert all four held flags
are false within one frame and that a subsequent jump press still produces a jump (the
"jump stopped responding" regression).
**Notes:** auto-pausing on hidden-tab is *not* part of this entry (it would need `G.state` access);
R06 only makes input state safe. Mentioned so the worker does not scope-creep.

### R07 — Audio: backgrounded-tab note pile-up, no resume, mute-before-init

**Files:** `src/audio.js`.
**Symptoms:** (a) switch tabs for a few seconds and the music becomes a distorted cluster — the
`setInterval` scheduler is throttled to ~1 Hz while hidden, but `musicNextTime` falls far behind
`ctx.currentTime`, so each tick schedules ~1 s of notes **in the past**, which Web Audio starts
immediately, all at once. (b) If the `AudioContext` is created suspended, nothing ever calls
`ctx.resume()` → the game is silent forever. (c) Pressing **M** on the title before `init()` is a
silent no-op (`toggleMute` returns early when `!inited`), so the HUD never shows `MUTED`.
**Fix:** (a) at the top of the scheduler tick, `if (musicNextTime < ctx.currentTime) musicNextTime = ctx.currentTime + 0.05;`
(b) in `init()`, if `ctx.state === 'suspended'` call `ctx.resume()`; also re-resume at the start of
`musicStart()`. (c) let `toggleMute()` always flip `this.muted` and apply the gain when inited; in
`init()` set `master.gain.value = this.muted ? 0 : MASTER_LEVEL`.
**Check `R07`:** (a) simulate scheduler drift — set `musicNextTime` 2 s behind `currentTime`, run one
tick, assert no tone is scheduled at `t0 < currentTime` and that `musicNextTime` resynced;
(b/c) with a fake `AudioContext` whose `state` is `'suspended'`, assert `resume()` was called; call
`toggleMute()` before `init()` and assert `audio.muted === true` and that the gain created by the
later `init()` is 0.
**Notes:** `sfx()` ignoring `this.muted` is fine (master gain gates it) — do not "fix" that.

### R08 — The gate trigger covers only the bottom 16 px of a 112 px gate

**Files:** `src/main.js:266-272`.
**Symptom:** you can jump through the entire visible arch and land behind the gate without clearing
the level; meanwhile the trigger extends 80 px *below* the floor where nothing can be.
**Mechanism:** `drawGate` treats `gate.y` as the row-12 tile top and draws from `y - 96` to `y + 16`
(measured art extent `y -103..+16`), but the rect is `gate.y … gate.y + 80`. Two audits reached this
independently. The numbers are tuned to row 12 and break for any other `G` row.
**Fix:** derive the band from the art: `p.y + p.h > gate.y - 64 && p.y < gate.y + 16` (keep the
horizontal `gate.x … gate.x + 32`, which matches the 2-tile art).
**Check `R08`:** a big player passing through the arch rows (`gate.y - 64 … gate.y`) triggers
`LEVEL_CLEAR`; standing on the ground 2 tiles to the left does not; a player at `gate.y + 40`
(below the floor) does not.
**Notes:** after this, `main.js:268`'s magic numbers should reference the gate height from one place
(a `GATE_H`-style local or `config.js`) so R34's doc text has something true to point at.

### R09 — Boss speed: hard-coded 60 overrides `BOSS_SPEED`

**Files:** `src/enemy.js:96`.
**Symptom:** after its first hop the boss walks at 60 px/s forever instead of the configured
`BOSS_SPEED = 40` — 50% too fast, and nothing ever restores a walk speed.
**Mechanism:** `b.vx = Math.sign(player.x - b.x) * 60 || BOSS_SPEED;` — the `|| BOSS_SPEED` branch
only fires when `dx === 0` exactly, and in that case the boss always hops **right** regardless of
which way it was moving.
**Evidence:** `boss after 200s … vx -60`.
**Fix:** `const dir = Math.sign(player.x - b.x) || Math.sign(b.vx) || 1; b.vx = dir * BOSS_SPEED;`
Drop the literal 60 (decision: numeric values live in `config.js`; if a distinct hop speed is
wanted, add `BOSS_HOP_VX` to `config.js` rather than inlining a number).
**Check `R09`:** after a hop, `Math.abs(b.vx)` equals the configured speed; with `player.x === b.x`
exactly, the boss continues in its previous direction instead of always right.

### R16 — Text renderer: every glyph is too wide for its cell  `[BROWSER]`

**Files:** `src/sprites.js:318-338` (+ `src/render.js:34-40` `textW`/`centerText`).
**Symptom:** half-eaten characters. The HUD reads as clipped glyphs where `0`/`C`, `8`/`B`, `1`/`l`
blur together; the `—` in the level banner and the `+` in popups degrade worst; the scale-3 title
logo is a mosaic.
**Mechanism (measured, not estimated):** cells are 12 px wide at `font='24px monospace'`, but no
mainstream monospace has a 0.5em advance — Menlo (the macOS Chrome **and** Safari default) is
**14.45 px** @24, Courier 14.40, SF Mono 14.84, DejaVu Sans Mono (Linux) 14.45, Consolas (Windows)
13.20. So 2.4-2.8 px of every glyph is destroyed four ways: ink past the cell is dropped; the last
glyph is additionally clipped by `off.width = text.length * 12`; left-to-right `fillText` paints
glyph *i*'s overflow into cell *i+1*'s source rect, so it blits as the **wrong character**; and the
12→6 nearest-neighbour blit samples only ~4 of 12 source columns. Separately, `scale` yields
non-integer blit ratios (scale 1 = 2:1 **down**, scale 3 = 1.5x **up**) → uneven stem widths.
**Fix (decision 4 — authored bitmap font):** replace the canvas-text cache with a procedural 5x7
(or 6x12) bitmap font drawn with `fillRect`, covering `A-Z 0-9 space : . , - + / x ←` and the `—`
used in the banner. This is deterministic on every platform, has zero dependencies, and removes the
offscreen-canvas cache, the pitch problem, the smear and the fractional-scale problem in one move.
Keep `drawPixelText`'s public signature and make `textW`/`centerText` derive from the new pitch.
Preserve the Node-safe path (`typeof document === 'undefined'` early return) — the harness relies on
it; prefer making the font renderer pure `fillRect` so it works headless with no DOM at all.
Also fix in passing: hoist `ctx.imageSmoothingEnabled = false` out of the per-character loop
(`:333-334`, it is destination state and already set at `main.js:23`), and delete the now-unused
`textCache` (or cap it: `if (textCache.size > 128) textCache.clear()`) — it never evicted, and a
5-minute session accumulated 150-250 canvases ≈ 2.0-3.3 MB, surviving restarts (bounded, not
runaway, but never freed).
**Deviation to record:** `RESUME.md:13` (deviation #2) records the 12x24 cell / 12-px advance as
"exactly per spec", and `architecture.md:115` says "draw back at 1/3" (it is actually 1/2). R34
supersedes both.
**Check `R16`:** render `SCORE 000000` and `VEGGIE BROS.` at scales 1/2/3 into a pixel buffer and
assert (a) every glyph occupies exactly its cell (no ink in the neighbour cell), (b) no glyph column
is empty where ink is expected, (c) `textW()` equals the measured ink span, (d) zero
`document.createElement('canvas')` calls for text.
**Notes:** R18/R19/R24 edit text callers — land this first.

Gotchas, all discovered the hard way:

1. **Start synthetic time from `performance.now()`.** Starting at 0 makes `main.js:331`'s
   `dt = (now - last)/1000` hugely negative against `last = performance.now()`, so the accumulator
   swallows the first several `update()` calls. Symptom: flags look "consumed late", states look like
   they fall through — it is the harness, not the game. The orchestrator lost three runs to this.
2. **`window` listeners must be captured**, not no-oped, or R06/R13/R14 checks cannot dispatch
   `keydown` / `blur`. Keep them in arrays and fire them with synthetic event objects
   (`{ key, code, metaKey, preventDefault(){}, repeat:false }`).
3. **Prefer direct unit checks over whole-loop checks.** `config.js` `levels.js` `level.js`
   `player.js` `enemy.js` `items.js` `camera.js` are DOM-free — construct a `parseLevel({...})`
   synthetic map and call `updatePlayer` / `updateTurnip` / `updateItems` directly. Most checks
   (R01-R03, R08-R09, R21-R22, R28-R31, SMOKE) need nothing from `main.js`.
4. **`G` is not exported from `main.js`.** Loop-level state was inferred from the audio spy
   (`musicStart`/`musicStop`/`sfx:<name>`) and from which overlay strings were *created* (the old
   text cache calls `fillText` only when a string is new, so string creation == first frame of that
   state — a reliable transition detector, but it breaks the moment R16 removes the cache).
   **Sanctioned shortcut:** add `export` to the `const G = {…}` in `main.js` (one word, no behaviour
   change) so loop checks can read `G.state` / `G.items` / `G.player` directly. Say so in the commit
   message, note it in §11, and let R32 own it permanently. Do not build fragile pixel-guessing
   detectors instead of that one word.
5. **`drawPixelText` returns early when `typeof document === 'undefined'`** — keep that Node path
   alive even after R16's bitmap font, or the pure-module checks stop working.
6. **`#game`'s context is the destination canvas.** `mkEl()` gives it a non-recording context; for the
   `[BROWSER]`-adjacent geometry checks (R16/R21/R22/R23/R24) wire a recorder in —
   `els.get('game').getContext = () => mkCtx(rec)` before the frames you want to inspect — and assert

Audited and confirmed sound. A worker proposing a change here must justify it against this list.

- **No tunnelling.** Worst per-step displacement is 7 px vs `TILE` 16, and `dt` is always exactly
  `STEP` (`main.js:335-337`), so there is no variable-dt path. Jump 10.7, hurt/kill 6.7, stomp 6.0,
